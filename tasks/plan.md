## Architecture decisions carried into implementation

- Use a TypeScript monorepo with React web, modular-monolith API, asynchronous worker, shared contracts, domain packages, simulation schema, model runtime, UI system, and Bicep infrastructure.
- Use Microsoft Entra External ID for authentication and PostgreSQL application authorization plus PostgreSQL RLS for tenant isolation.
- Use private Azure Blob Storage for files, PostgreSQL plus `pgvector` for MVP retrieval, Azure Service Bus for jobs, Key Vault for secrets, and Application Insights/Log Analytics for telemetry.
- Keep provider-specific code behind ports. Domain code must not import Azure SDKs, React, Babylon.js, database clients, or provider AI types.
- Use glTF/GLB as the canonical model format, Babylon.js as the initial runtime candidate, WebGL2 as the baseline, and a text/reduced-complexity equivalent for every certification-critical 3D activity.
- Use declarative, server-authoritative simulation. The browser sends semantic actions; the server owns state, sequence, scoring, and certification evidence.
- Use Azure OpenAI/Microsoft Foundry through an internal AI gateway. LLM conversion of PDFs/handbooks into training content is a core MVP workflow; output is structured, cited, validated, draft-only, and never published without human approval.
- Treat 3D model preparation, browser rendering, semantic interaction, and certification-equivalent access as core MVP behavior. Reconstruction adapters remain evidence-gated but are not removed from MVP scope.
- Use immutable course, model, simulation, assessment, policy, and release versions. Credential issuance is transactional and idempotent.
- Use an online issuer lookup and QR/URL for MVP credential verification. Do not claim portable cryptographic credentials, accreditation, or licensure.
