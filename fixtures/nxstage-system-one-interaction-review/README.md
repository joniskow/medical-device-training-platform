# NxStage interaction review model

This is an isolated, unmeasured visual reconstruction for review. It is separate from the shared interactive and cinematic assets. Its distinct preview model version, model manifest, and draft office scene are bound to the GLB hash. Version 3 adds the approximate raised rear enclosure and the visible lower portion of the pole; version 2 corrected the front caster hubs. It has not been approved for production or clinical instruction.

The model contains the corrected cycler controls, upper handle and sliding door, lower cabinet and tub, PureFlow and warmer controls, and the rear switch. The curved front face and single row of vents are based on the supplied `20261020_130849.jpg` and `20261020_131018.jpg`; a fixed lower-cabinet housing is based on `20261020_130843.jpg` and `20261020_131015.jpg`. Rear perforations, louvers, and an external canister and tubing are based on `20261020_131259.jpg` and `20261020_131328.jpg`. Their dimensions and the tubing route are estimated, and the front's shading is illustrative. The warmer bars are an illustrative local preview response; electrical power, heating, fluid operation, treatment values, and the cartridge compartment are not simulated. The rear switch travel and on/off orientation, dimensions, and hidden surfaces remain estimates. The label shapes on the rear panel are intentionally unreadable.

To run the preserved model locally, install the workspace dependencies, build the model-runtime package, and run `node tools/serve-nxstage-interaction-review.mjs`. Open `http://127.0.0.1:4215/` (or set `NXSTAGE_REVIEW_PORT` before starting it). The server compiles the current player source and serves this fixture; it does not require the earlier candidate folders. The warmer response and focus buttons are local review features. The initial and reset views fit the complete device; **Fit model** fits it from the current angle. The focus shortcuts orient the view toward the front or rear of the chosen part. Focusing the lower panel while the cabinet is closed explains that part of the panel may be obscured; the visible controls remain accessible.

**Focus tub** looks down into the tub when it has been pulled out, and uses a front view when it is pushed in. The browser check verifies a touch on the exposed front rim, a mouse click on the exposed side, and partial mouse drags from left and right oblique views, as well as the cabinet interlock. `tub-open-review.png` records the open view; the empty container and its unmeasured travel are visual approximations.

**Focus door handle** selects the upper handle and frames it with room for its estimated movement. Desktop and phone checks verify that the raised handle stays in view and that the named controls remain available. The phone check also touches the visible 3D bar directly to raise it.

**Magnify panel controls** offers closer 3D views of the front-panel groups and the lower panel's arrows and GO/STOP buttons. The lower close-ups require the cabinet door to be fully open. **Focus control panel** or **Focus lower panel** returns to the corresponding full panel. On the emulated 390-pixel phone viewport, the Volume Toggle grew from approximately 13 to 59 CSS pixels wide; tests check that every group member remains visible and directly reachable. These are browser-emulation measurements, not a substitute for testing with people on physical devices.

To view the same preserved model in the office scene, build the contracts package and run `node tools/serve-nxstage-interaction-office.mjs`, then open `http://127.0.0.1:4216/` (or set `NXSTAGE_OFFICE_REVIEW_PORT`). This review serves the saved model, hash-bound scene and `office-background-review.mp4`, compiles the current demo source, and uses the supplied clinical draft image when it loads. The background is preserved separately because the shared video is being changed independently; both the server and scene builder verify its hash. It omits older static composite thumbnails because those show a different model. **Enlarge scene** and **Close view** retain the same live model state. After selecting **Interact with model**, **Explore model** allows rotation and zoom against a neutral backdrop and offers **Focus door handle** and **Magnify panel controls**; **Return to office** restores the aligned photo and camera without resetting the model. The review opts into preservation of the imported GLB root transform so placement does not mirror the model; other scene bindings retain their existing behavior until separately reconciled.

For the office browser check, start both server and test with `OFFICE_REVIEW_TEST=1`, then run `node tools/check-nxstage-interaction-office-browser.mjs`. It covers switch and warmer controls, doors and tub including partial-position feedback, keyboard navigation and button activation and cancellation on the 3D canvas, exploration and reset, direct phone touch on the visible upper handle and door, direct touch on all eleven magnified front-panel buttons, phone-sized touch rotation and pinch zoom including cancellation, and enlarged and close views. The photo-backed variant also checks the failed-photo fallback.

To stage a portable copy of the office walkthrough review, start the ordinary office review server and run `node tools/package-nxstage-interaction-review.mjs`. It includes the walkthrough video and room image, verifies the served model, manifest, scene, and video hashes, rejects a stale or test-enabled preview, and writes `output/nxstage-interaction-review/portable-office/` (or the path in `NXSTAGE_PACKAGE_FOLDER`). Run `node server.mjs` inside that folder to serve the packaged review locally; set `NXSTAGE_PORTABLE_PORT` if the default port is occupied. The package is for review and does not replace or publish the shared application assets.

With the server running, `node tools/check-nxstage-interaction-review-transfer.mjs`, `node tools/check-nxstage-interaction-review-touch.mjs`, `node tools/check-nxstage-interaction-review-mobile.mjs`, and `node tools/check-nxstage-interaction-review-browser.mjs` verify transfer integrity and interaction behavior. The desktop and phone-viewport browser checks directly press all eleven front-panel targets at their visible centers and check hit locations, depression, activation and release. The mobile check also presses the visible warmer button at a 320-by-568 viewport and verifies that switching from a tub drag to a pinch restores its previous position without submitting a movement. The browser checks use Chrome emulation, not physical devices; the broader and mobile checks save review screenshots under `output/nxstage-interaction-review/`.

The authoring source is `blender/nxstage_system_one_interaction_review.py`. It expects the user's 20 source photographs in `output/nxstage-system-one-photos/`; those source files are not included in this fixture. It writes to the separate `nxstage-system-one-interaction-review` asset folder and saves a uniquely named Blender file. To rebuild without rendering, set `NXSTAGE_SKIP_RENDER=1` and run Blender from the workspace root with that script. `NXSTAGE_OUTPUT_ROOT` can redirect all generated output to a separate directory.

After rebuilding this fixture, run:

```text
pnpm --filter @medical-device/model-runtime build
pnpm --filter @medical-device/contracts build
node tools/build-nxstage-interaction-review.mjs
node tools/build-nxstage-interaction-review-scene.mjs
node tools/check-nxstage-interaction-review.mjs
```

The model builder updates only this review fixture by default. The scene builder checks the background video and cue bindings before updating this review scene; neither builder updates the shared release assets. The panel and rear screenshots document this candidate's appearance and are review evidence, not measured references.

Run `node tools/check-nxstage-interaction-integration.mjs` to compare the current shared interactive fixture and scene with this review. It verifies each model/manifest/scene binding and writes `output/nxstage-interaction-review/integration-report.json` with target and cue differences, including changed properties and node paths for IDs shared by both models. Matching IDs or metadata do not establish equivalent geometry or meaning. Reconciliation must include scene cues, static asset bindings and any persisted sessions; target IDs cannot be substituted automatically. This check does not promote or overwrite either model.
