## Workflows

- **Create learning:** upload PDFs or select a processed source, create a course, generate a cited draft, and display lessons, knowledge checks, explanations and the complete generated video plan. Each video lesson exposes the script/shot-plan review and speech controls: pace, emphasis, pronunciation aliases, anchored pauses and speech-only defaults. Save with optimistic revision checks, render a hosted rough cut, play private video with selectable captions, explicitly accept the reviewed current cut, then render final output. Saved hosted renders reopen without regeneration. Production-input edits hide stale playback and require a new review. Independent final review and publication remain in the full editor.
- **Create a 3D scene:** upload photos/video, inspect and approve source media, select approved sources, submit reconstruction, reopen saved builds, and preview the actual private GLB. Choose a sample room, light/dark studio, or local background image. Keyboard camera controls accompany pointer controls.
- **Generate a background:** select an approved company model and reference video, then submit the configured video/Speech generation pipeline. The scene uses actual selected asset IDs and source hashes; a bundled example manifest supplies only camera/render defaults. Generated video and narration are delivered through authenticated API requests.
- **Company & services:** 78 selectable actions from the deployed public API catalogue plus core content operations, grouped into seven service areas. Native forms cover reports, private exports, connections, integrations, notifications, privacy/retention, discovery, learning and credentials. Load company resource choices and saved settings, review and confirm writes, and see real results or explicit failures. Interactive authoring, assessments, simulations and account verification retain their guided tools; application-identity automation endpoints are identified separately.

Learning customization includes audience, prior knowledge, format, requested video duration, objective, setting, source revision, visual style and reviewed terminology. Video generation first saves a validated instructional brief bound to the exact selected sources and approved media. Document-only generation is the default when approved media is unavailable. Scene presets change the actual prompt; voice selection and the speech toggle change the actual generation request.

Inputs have useful defaults. File selection, company membership, review confirmation, and asset approval come from the user or server. Source approval is not inferred from a successful malware scan. Reconstruction and background generation also require registered derivative-use rights. The workspace records explicit rights attestations through `POST /api/v1/media-review/{asset-or-model-id}/rights`, using an idempotency key and `{targetKind,sourceHash,ownerName,useScope,confirmed:true}`. The existing content-role and tenant boundary protects the endpoint. Asset/model identity and hash are checked in a tenant transaction; replay is deduplicated, changed intent conflicts, inactive rights cannot be restored, and an audit event is stored atomically. Confirmation starts unchecked. This attestation does not approve source media or generated geometry.

## Verification and deployment

Run `node node_modules/typescript/bin/tsc -p apps/web --noEmit` and the equivalent API check. Build the normal app, or run `node tools/build-admin-ui.mjs --base-image=<currently-serving-API-image-with-sha256-digest>` for a small admin deployment context at `output/admin-deploy`. That helper preserves the chosen backend image and adds the narrowly scoped usage-rights endpoint required by the workspace. Its guarded route patch fails if the router does not match the expected base. The overlay includes updated sign-in routing and compressed browser bundles.

`node tools/check-admin-workspace-browser.mjs` runs dedicated headless Chrome with explicitly labeled API fixtures. It checks upload/hash binding, course results, speech settings/revisions/rendering/captions/listening confirmation/stale playback/saved playback, reconstruction and actual GLB rendering, backgrounds, report failure visibility, organization isolation and cleanup, and widths 320/768/1024/1440. Set `ADMIN_TEST_NO_MEMBERSHIP=1` to verify sign-out remains available when a signed-in account has no company. Run `node tools/check-admin-rights.mjs` for rights validation/replay/security checks and `node tools/check-admin-rights-postgres.mjs` for actual HTTP, restricted PostgreSQL role, tenant isolation, audit and withdrawal checks using the local test database. Screenshots are in `output/admin-browser`. Browser fixtures do not establish live provider acceptance.

Hosted rendering currently supports synthesized narration with speech-only audio. Recorded narration and independently reviewed source-sound cue mixing remain available through the advanced CLI rendering workflow described in [lesson-audio.md](lesson-audio.md); the simple panel explicitly reports this boundary and rejects an unsupported hosted mix before creating a job. Author-entered cue IDs cannot manufacture trusted review evidence.
