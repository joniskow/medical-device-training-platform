# Personal historical credential wallet

`GET /api/v1/my-credentials` returns only the signed-in personal account's credentials across issuers. It runs after the personal-account access check and before organization membership resolution. It accepts only a single optional `after` cursor, rejects learner/issuer selectors and mutation methods, and requires the wallet/account services. The endpoint never grants course access or credential administrative authority.

A private routing table maps credential IDs to their existing learner and organization. A trigger synchronizes inserts/ownership routing changes in the credential transaction; cascading deletion removes routes. Migration backfills existing credentials. Runtime receives no direct routing-table privileges. A fixed-search-path SECURITY DEFINER reader with PUBLIC execution revoked scans at most 51 owner routes, returns at most 50 entries, sets tenant context for each authoritative credential lookup and restores caller user/tenant settings. It rechecks credential ownership and an ACTIVE personal account. Worker bootstrap grants only reader execution.

The explicit projection contains credential identity, immutable issuer/title information, release/course/policy references, current lifecycle status, issuance/expiration, supersession, sharing state and intended-use text. It excludes assessment answers, evidence documents and other learners. Expiration is evaluated at read time. Historical records remain readable despite suspended/removed memberships, suspended training or issuer, and retired releases; this does not restore those other privileges. Issuer names use the issuance policy snapshot, not the current organization profile.

`/wallet` is linked from account, learner and candidate-training pages. It shows paged historical records with safe text rendering and existing enabled public verification links. It sends no selected-organization header, clears records on refresh/access failure and fences pending responses after sign-out/account changes. Public sharing disabled at issuance stays disabled. The independent wallet now provides confirmed enable/disable sharing, copy-link and QR controls, described below.

## Evidence and limits

`tools/check-candidate-enrollment.mjs` uses restricted-runtime readers and HTTP with controlled authentication. It first issues a real credential through assessment completion, then checks owner-only historical access, suspended membership/enrollment/issuer and retired release behavior, expired/revoked status, locked-account denial, exact projection keys, denied direct table reads/PUBLIC execution, pooled context restoration and migration backfill. Another 52 synthetic records exercise two-issuer pagination and superseded status; those seeded records are not evidence of 52 real issuances.

`tools/check-personal-wallet-browser.mjs` uses controlled Chrome responses for anonymous denial, no organization header, inert issuer/title text, lifecycle display, sharing visibility, pagination, access loss and late-response sign-out. Candidate and learner browser regressions, credential lifecycle integration, workspace build and architecture checks pass locally. Run `pnpm personal-wallet:validate` for the wallet checks. Live identity-provider/Azure acceptance and full physical-device/accessibility acceptance remain open.


## Independent owner sharing and QR

`POST /api/v1/my-credentials/{credentialId}/sharing` accepts only `enabled` and a nonnegative integer `revision`, requires an idempotency key, and rejects query selectors and body authority fields. It runs after account validation and before organization membership resolution. A narrow fixed-search-path resolver with PUBLIC execution revoked derives the issuer from private routing metadata, checks the ACTIVE personal account and rechecks authoritative credential ownership under tenant context, restoring caller context afterward. Supplied organization headers cannot select the issuer.

The endpoint delegates to the existing credential sharing transaction, preserving ownership checks, revision conflicts, transactional verification-projection/event/audit updates, idempotent current-state replay and original lifecycle status. Historical owners can withdraw or enable policy-permitted verification even when membership, enrollment, release or issuer no longer permits learning. This grants no learning or administrative access. Revoked credentials remain revoked when shared.

The wallet requires explicit confirmation for changes, preserves the request key after an interrupted response, locks conflicting controls until refresh, and clears content on access loss. It uses the existing QR renderer and provides a copy-link button. Successful withdrawal removes the link and canvas. Sign-out/identity fences apply to pending writes and QR rendering. Employer discovery is explicitly separate.

Expanded restricted-runtime/HTTP tests cover forged organization headers, rejected extra body authority fields, concurrent duplicate sharing, stale revisions, delayed replay after a later change, revoked-status preservation, missing targets, locked accounts, denied PUBLIC resolver execution and restored context. Existing credential tests cover audit failure rollback. Chrome checks cover confirmation cancellation, retry identity, conflicts, independently decoding the actual QR with jsQR, withdrawal and sign-out during a pending write. Full build, architecture, credential and learner regressions pass locally. Physical scanning and live deployed acceptance remain open.
