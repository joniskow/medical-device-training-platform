# Simulation procedure editor and local preview

The author workspace renders a no-code editor when the draft already contains a structured, model-bound `simulation.definition`. It preserves model/simulation identities and edits step titles, hints, effective step/fault points, maximum score, passing threshold, starting step, successor selection, semantic action type/component/value/step reference/transform, fault diagnosis/resolution, and equivalent keyboard instructions. Score edits update both the descriptive points and the effective scoring map. Existing preconditions, completion rules, trigger associations, component definitions are retained. Fault failure rules can be set to allow correction or invalidate the attempt.

The editor uses the shared production simulation-schema validator. Findings are displayed using safe text. Edits invalidate local preview state. Reset validates and clones the current definition; preview action buttons use production deterministic replay with fresh action IDs, sequence and nonce, showing rejection, score, current step/fault and completion. Preview sends no learner session/action requests and creates no completion or credential evidence. It remains independent of the existing draft autosave/review/publication authorization gates.

The runtime now selects between multiple successors using mutually exclusive destination preconditions. Next step chooses a single successor; branch destination checkboxes configure multiple successors. See the variable and branch semantics below.

## Procedure and fault creation (2026-10-30)

Within an existing bound definition, authors can insert a required step after any step with at most one successor. Insertion preserves the successor, moves terminal completion when appropriate, creates a stable ID and zero-point scoring entry, and focuses the new step. Authors must supply equivalent instructions before preview/publication. Maximum score and passing threshold remain explicit author choices.

Authors can add one fault at an unoccupied trigger step. The editor creates linked trigger, required-fault, score and equivalent-instruction entries with a correction-allowed default. Diagnosis and resolution remain editable. Blank, malformed or unknown-fault equivalent instructions now fail shared validation, including publication.

Confirmed fault removal cleans trigger references, completion, score and instructions. Step removal preserves predecessor links and terminal/start references and cleans completion, score and instructions. Removal is blocked for the last step, an initial step without one successor, multiple successors, attached faults or another action referring to that step. Authors must resolve these dependencies first. Cancellation preserves the draft. Removal prompts authors to review maximum score; it does not silently change the certification threshold.

The existing fieldset/label/button styles are retained. Structural changes preserve editor position and move focus to the created or surviving step/fault; local preview is discarded. Chrome tests save and replay an authored terminal step plus fault, check blank-instruction rejection, focus, cancellation, attached-fault blocking, reference cleanup, restored predecessor completion, retained model identity and no learner API requests. Build, schema/publication negative cases, architecture, publication PostgreSQL and fault PostgreSQL regressions pass locally. Full initial simulation creation/model selection, branch/variable editing and deployed acceptance remain open.

## Initial creation from an approved model (2026-10-30)

Saved editable drafts without a simulation show an approved-model picker with 50-item cursor pagination. Authors confirm creation; an interrupted response retains the request key for the same selection. Unsaved edits block creation. Conflicts require reloading; successful creation reloads the draft and focuses the procedure editor. Session and editor changes fence late responses. Model IDs render as inert text.

GET /api/v1/approved-models returns only modelVersionId and componentCount, with an optional nextCursor. POST /api/v1/course-versions/{id}/simulation accepts exactly revision, modelVersionId and confirmed:true, plus Idempotency-Key. Both require an authenticated author membership. The server derives the model manifest/hash/component IDs from the current tenant's APPROVED record, rechecks the draft revision/status and rejects an existing simulation or conflicting model binding. Creation locks the draft and model, adds a simulation module/activity and records an audit event in the same transaction. Identical retries return their prior result without overwriting later edits.

The starter definition is deliberately incomplete: one zero-point selection step and blank equivalent instructions. Authors must supply reviewed procedure content, score, source citations and certification policy through the existing authoring flow. No publication approval, completion evidence or credential is granted by creation. Publication still rechecks model approval and hash. Existing simulations cannot be rebound using this operation.

## Typed variables and conditional successors (2026-10-30)

Authors can add boolean, number and string scenario variables, edit initial values, set step preconditions and assignments, and set assignments applied after fault resolution. Variable types remain fixed; referenced variables cannot be removed until their rules are cleared. Values are declarative constants, never executable expressions or client-supplied assignments. Invalid numbers, unknown variables and type changes fail shared validation.

A step with multiple successors chooses the one destination whose preconditions all match the resulting state. Each pair of destinations must disagree on at least one shared variable condition, preventing overlapping branches. Step assignments apply before choosing the successor; a step that triggers a fault waits until resolution, applies fault assignments, then chooses. If no destination matches, the triggering action or fault resolution is rejected with no score, variable, sequence or completion changes. A single successor retains existing behavior, including checking its preconditions when its action is attempted. Cycles and unreachable steps remain blocked. Imported multi-successor definitions without exclusive guards now fail validation instead of silently choosing their first successor.

Required-on-every-successful-path checkboxes control global step/fault completion requirements. Alternative-path steps should not all be marked globally required. Every step and fault, including alternative branches, needs equivalent instructions. Scores remain the sum of accepted actions against the explicit published maximum and passing threshold; no automatic normalization hides differences between paths. Authors must preview each path and review attainable scores. The controls support deterministic state-based branches, not arbitrary scripting or a complete visual story graph/learner-choice system.

Local verification: tools/check-simulation-branches.mjs covers both outcomes, typed step/fault effects, client-variable spoofing, repeatable replay, score preservation, unmatched step/fault rollback, invalid variables, ambiguous/cyclic graphs and missing alternative-path instructions. The Chrome author test creates a variable, authors exclusive branch conditions, saves the graph and previews both pass and below-threshold outcomes, then removes rules and restores the linear route. tools/check-e4-postgres-session.mjs --branches publishes a branched fixture, proves the alternate step and variable state are persisted, and exercises completion/credential issuance, replay/resume and lifecycle checks. This PostgreSQL rehearsal uses the fixture administrator and controlled storage/authentication. Build, schema, architecture and published fault-invalidation regressions pass locally. Deployed/physical-device acceptance and comprehensive every-path author tooling remain outstanding.

## Bounded scenario-path diagnostics (2026-10-30)

Check scenario paths runs the production transition function locally with correct configured actions. The first case uses the draft's configured initial values. Remaining hypothetical cases cover the equality partitions of variables referenced by preconditions: booleans, compared number/string constants, and one representative for all other values. Constant step/fault assignments are applied by the engine. No draft values, learner sessions, evidence, credentials or publication approvals are changed.

Each case reports passing, below threshold, missing requirements, blocked or limit reached, together with score, initial variables, completed steps and missing step/fault requirements. Coverage lists steps/faults not reached in the checked cases. This can reveal a branch made unreachable by a constant effect or requirements that incorrectly demand both alternatives. Edits discard the report. All author content is rendered as text in expandable case details.

Work is capped at 128 cases and 4,096 semantic actions per check. Reports explicitly distinguish complete equality-case coverage from partial checks. A complete check means coverage of the current declarative variable/constant-transition model using correct actions; it does not mean every learner mistake, model geometry/transform capability, visual story interaction or external device scenario was exercised. The engine still rejects invalid definitions before analysis. Diagnostics are author guidance, not a publication sign-off or a certification result.

Verification: tools/check-simulation-branches.mjs covers configured-case ordering, both branches, fault coverage, constant-effect unreachable branches, missing requirements, below-threshold outcomes, unmatched string cases, invalid definitions, scenario limits, the 4,096-action limit and unchanged input definitions. ## Learner semantic-action transport (2026-10-30)

The published learner session now accepts every action type exposed by the editor: select_component, transform_component, open_component, inspect_component, complete_step, acknowledge_fault, diagnose_fault, resolve_fault and request_hint. Reset remains a non-scoring model control. Optional action value and step reference are carried end to end and checked against the published requirement. Duplicate identity includes these fields, so a changed value/reference cannot reuse a cached result. HTTP accepts only documented fields and bounded scalar values; client scores and arbitrary payload objects are rejected.

The learner keyboard form offers the current action type plus optional value/reference and numeric transform fields. It does not expose expected answers. Selection and transforms require a known component; other semantic actions can be component-free. Every supplied transform is checked against approved component bounds before being applied. A semantic open/inspection/acknowledgement is recorded as a procedure action; geometry changes only when a permitted transform is supplied. Navigation selection and hint requests remain non-scoring unless they are the current published requirement. Diagnosis/resolution actions go through the shared fault state machine and failure rule.

Shared author validation rejects actions that the HTTP contract cannot carry: component-free selection/transforms, empty transforms, transforms without a component, overlength component IDs or values/references. This does not yet prove that every configured transform matches the actual model's permitted range or snapping rules; model-aware publication/preview validation remains outstanding.

Local evidence: tools/check-e4-postgres-session.mjs --semantic-actions publishes a fixture with all nine types, semantic fault diagnosis/resolution, component-free actions, required values/references and a bounded transform. It checks wrong-value rejection, repeated-request identity behavior, changed-reference denial, completion, resume and credential issuance. This uses the fixture administrator and controlled authentication/storage. HTTP tests cover every added type and forged-score/object rejection. Chrome uses a controlled session service to verify keyboard entry/submission of semantic values/references plus existing model selection, transforms, completion and resume. Build, model action/persistence/player contracts, pure schema, author Chrome and fault-invalidation regressions pass locally. Real-provider/deployed/physical-device acceptance remains open.

## Approved-model transform validation (2026-10-30)

Author preview now combines structural validation with model-binding validation. The bound model manifest must be available and agree with the simulation's model ID, hash and exact component set. Every step action and fault diagnosis/resolution transform is evaluated using the same applyPermittedTransform function as learner execution. Unsupported axes, invalid bounds/increments, impossible initial zero poses, out-of-range results and values that normalize to a different value block manual preview and scenario-path analysis. Noncanonical findings show the permitted snapped value. The editor does not silently rewrite the procedure.

Publication repeats this check against the current APPROVED database model manifest under a shared row lock, before materializing model/release artifacts or runtime records. The database record is authoritative even when the editable draft contains a different manifest. Existing immutable releases retain their bound model snapshots; this change does not retroactively rewrite them. Semantic actions without transforms remain procedure records and do not imply geometry changes.

Local verification: tools/check-simulation-model-actions.mjs checks actual fixture limits, snapping, endpoints, semantic-action transforms, fault transforms, exact component/hash identity, malformed rules and initial pose. Chrome verifies both manual preview and scenario-path checks reject invalid transforms and recover after correction. tools/check-e4-postgres-session.mjs --model-validation deliberately restricts the database model while keeping the draft's permissive copy, proves publication is blocked with no release/runtime-definition/publication-event rows, then restores valid limits and completes the standard learner/credential lifecycle rehearsal. Full build, publication/successor regression, all-semantic-actions rehearsal, model manifest contract, pure schema and architecture pass locally. ## Visual procedure graph (2026-10-30)

The editor now includes a directed graph of its existing procedure definition. Cards show title, start/required/end markers, destination preconditions and attached faults. Arrows show configured successors; terminal markers explicitly do not imply a passing result. Selecting a card with mouse, Enter or Space focuses its step editor. An expandable text outline retains full labels, conditions and transition destinations for assistive technology and long text.

Transition controls add links or remove them with confirmation. Duplicate links, self-links and cycles are rejected without changing the draft. Successful changes update terminal references, discard local preview, mark the draft dirty and rerender the same shared definition. Other findings, including unreachable steps and overlapping destination conditions, remain visible through the production validator. Form edits refresh graph labels and links without replacing the focused field. Existing invalid cyclic drafts can still render for correction.

The graph has a bounded-height scrolling region; wide branches scroll locally rather than widening the page. It reuses existing colors, type and controls, with visible node focus and a secondary removal button. This is a procedure-graph view and transition editor, not a full narrative story/choice authoring system or 3D viewport.

## Visual 3D author preview (2026-10-30)

Saved editable drafts can load their approved model into a lazily loaded Babylon viewport. Accepted local procedure actions update the preview transforms/selection; reset restores the initial pose. Canvas selection is inspection only. No learner session, progress, score or credential is created. Draft edits invalidate the viewport; removal, sign-out and late responses dispose or fence the renderer. Text and keyboard preview remains available on loading errors.

GET /api/v1/course-versions/{id}/model-preview?revision={revision} requires author/reviewer access, exact saved revision, DRAFT/IN_REVIEW status, current approved model and matching model/hash binding. The service checks tenant object paths, projects the browser manifest with an explicit preview binding, and signs only the private GLB. URLs remain usable until their short expiry; withdrawal does not revoke an already issued URL instantly. The renderer retains byte-hash, geometry and component checks. The editor blocks loading unsaved changes.

## Unambiguous simulation identities (2026-10-30)

Validation now rejects duplicate model component IDs, component definitions, procedure step IDs and fault IDs. Publication also rejects duplicate component IDs in the bound manifest. Previously these checks tested Set.add's return value, which always returns the set; repeated IDs could therefore be accepted and graph lookup could resolve a different entry from execution. Checks now test membership before insertion and retain the first entry for diagnostic traversal without mutating the draft. Missing/non-array successor lists produce findings instead of throwing during graph traversal or terminal checks.

Regression tests reproduce the former acceptance bug, cover all identity categories, check nonmutation and malformed successor lists, and assert publication findings. The PostgreSQL rehearsal `node tools/check-e4-postgres-session.mjs --identity-validation` inserts a conflicting step, verifies publication rejection with no release/runtime/publication-event rows, restores valid content and completes the existing learner/credential lifecycle checks. It uses fixture administrator access and controlled authentication/storage, not deployed acceptance. Full build, schema, branches/path diagnostics, author Chrome and architecture checks pass. Full story/choice authoring remains outstanding; this correction protects its existing simulation prerequisite.
