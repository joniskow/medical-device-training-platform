# Narration delivery and audio finishing

Scene `narrationDelivery` saves pace (0.75–1.25), emphasis (`none`, `reduced`, `moderate`), observation pauses anchored after a unique exact script phrase (0–5000 ms), and terminology aliases. Author controls appear under each video lesson scene. An alias changes spoken pronunciation while the source transcript stays unchanged. Invalid or missing script anchors fail lesson validation. Azure receives escaped SSML; authors cannot inject SSML. Recorded narration must carry reviewed `delivery` metadata matching these controls; transcript equality alone cannot authorize reuse after a delivery edit. Default and explicitly default controls are equivalent, and JSON object-key reordering does not invalidate a recording.

The lesson renderer calls `synthesizeLessonAudio` with the scene script and delivery, then uses the returned measured duration for captions and timeline checks. It rejects the deterministic silent preview provider. Normalized WAV bytes are reviewable speech, with `LISTENING_REVIEW_REQUIRED` rather than automatic acceptance. `finishLessonAudio` also accepts actual recorded speech bytes. Input hashes include script, voice, delivery and profile; rendering binds its complete timeline/input revision and invalidates captions/reviews when these change.

Hosted default narration uses Jenny. Non-default emphasis selects Jane, one of the voices supporting the Azure SSML emphasis element; explicitly requesting emphasis with an unsupported voice rejects rather than silently ignoring the setting. See [Azure SSML voice and emphasis support](https://learn.microsoft.com/en-us/azure/cognitive-services/speech-service/speech-synthesis-markup-voice). The simple `/admin` learning result exposes delivery, saved settings, hosted rendering, captions and actual playback.

On 2026-11-07, private Azure smoke execution `mdt-personal-learning-smoke-j3cx45l` verified actual Jenny/Jane synthesis with pace, emphasis, anchored pauses and pronunciation aliases, followed by real FFmpeg finishing and peak measurement. The controlled version was 4.56 seconds versus 3.024 seconds for the normal version. Human listening review remains required; these engineering measurements do not certify pronunciation or clinical fidelity.

Profile `lesson-speech-v1` is an engineering default, not a clinical or speaker validation threshold. FFmpeg measures integrated loudness and true peak, flags input peak clipping risk (at least 0 dBTP), and applies measured two-pass loudness normalization to -16 LUFS, -1.5 dBTP and 7 LU range. Output is decoded again and measured; silence/nonfinite measurements and output peaks above -1 dBTP reject. This cannot restore already clipped words or certify speech intelligibility. Final timing must not truncate or accelerate speech to fit a scene.

Speech-only is the default. Each scene's `audioMix` controls this explicitly and optionally lists `instructionalSounds` with `assetVersionId`, `evidenceId`, `sourceStartSeconds`, `durationSeconds` and `atSeconds`. A sound must come from the scene's cited `source_video` visual. Source start must equal scene offset because that visual plays from its original beginning; cues cannot be shifted to imply a different device response. Intervals are bounded to 30 seconds and the scene duration. Alternate selected takes with source sounds reject until separately reviewed.

The renderer resolves every enabled cue against the trusted approved asset manifest's `verifiedInstructionalSounds` records (`evidenceId`, `sourceStartSeconds`, `durationSeconds`), probes for actual video/audio and interval bounds, extracts only that verified interval, and mixes it with narration. An author-entered evidence ID alone is insufficient. Asset approval records are a trusted CLI/developer input, using the same authority boundary as the existing `approved: true` media map; they must come from actual independent sound review. Captions retain the measured speech duration while a verified cue may play during the observation hold. Mixed bytes enter scene caching and `audioMix` enters revision invalidation. A mixed output receives a final loudness/peak pass; sound balance and factual meaning still need listening review. No background music is added. Set `LESSON_FFMPEG` and `LESSON_FFPROBE` to deployed tool paths when they are not in PATH.

Run the focused check after the contracts/worker build with `node tools/check-lesson-audio.mjs`. It exercises real decoding and measured normalization using a synthetic signal by default. Set `LESSON_RECORDED_FIXTURE` to reviewed recorded or synthesized speech for actual speech decoding. The synthetic signal does **not** establish correct pronunciation, absence of cut-off words, representative-speaker intelligibility or clinical fidelity. Real speech fixture acceptance and listening review on intended laptop/tablet speakers remain open: Windows speech fixture synthesis could not run in the sandbox and its escalation was declined. Review the exact final audio against the saved script, glossary, action transitions and device sound evidence before release.
