# Technical operating controls

Implementation: 2026-11-07. Local operational HTTP and PostgreSQL tests pass. Azure deployment, actual alert receipt, capacity, recovery RPO/RTO and secret rotation acceptance remain unproven; do not treat templates or this runbook as those rehearsals.

## Questions and signals

1. Are API requests succeeding within the bounded service envelope? `api_request` emits status, a bounded route category and duration; the workbook computes p95. `/healthz` is process liveness. `/readyz` checks required database relations/functions/permissions and storage, with a two-second probe bound and a coalesced five-second cache. Draining rejects new work before closing connections.
2. Why did work fail or stop? Correlation IDs propagate into existing job envelopes. `api_admission_denied`, `readiness_failed`, `job_failed` and `job_finished` distinguish availability, policy and execution failures. Do not log request bodies or caught exception objects.
3. Are paid calls safe to admit? PostgreSQL reservations serialize on a transaction advisory lock. Across replicas, at most four unexpired executions are admitted; conservative reserved/charged costs cannot exceed $500/month at admission, and admission at $400 emits `budget_threshold`. Azure's resource-group cost budget separately notifies on actual 80% and forecast 100%; it does not stop Azure spending.

Container Apps sends stdout JSON into its environment Log Analytics workspace. `infra/azure/monitoring.bicep` installs four workbooks from `infra/azure/operational-panels.json`, symptom/native-resource alerts, PostgreSQL/Service Bus AllMetrics export, a named email action group and Azure cost notifications. The workbooks cover every required API, queue, provider/cost and content/credential panel. The deployment must use the same isolated workspace configured on the Container Apps environment; otherwise queries can be empty or mix environments. No source text, provider errors, tokens, SAS URLs, raw addresses, raw job/learner identifiers or email addresses are emitted. Correlation values cross HTTP/job boundaries as before, but telemetry uses HMAC-SHA256 correlation hashes with matching API/worker operational secrets. Hashes are drilldown fields, never metric grouping dimensions. A failing log sink cannot turn a committed source, AI or billed receipt into a failed business call.

The worker samples at most 10,001 routing records once per minute under the existing designated non-super/non-bypass outbox-publisher role, using a read-only transaction and two-second SQL timeout. Pending/failed counts expose truncation and are labeled samples. No new global content/RLS bypass or SECURITY DEFINER function is introduced by telemetry. Separately, a two-second Service Bus peek examines at most 32 messages starting at sequence zero. It excludes deferred, future-scheduled and expired messages. Age starts at the later of enqueue time and scheduled eligibility time, excluding intentional admission deferral. Its age is the oldest eligible active message observed in that sample, not a guaranteed global oldest. If none qualifies, age is null and the observation is explicitly unknown; it never asserts an empty queue. Native ActiveMessages/dead-letter metrics provide separate broker stock measures. API/worker pool counts and Azure active/failed connections/storage metrics distinguish local pool pressure from native connection symptoms.

`infra/azure/api-availability-job.bicep` schedules a readiness probe every five minutes from the private Container Apps environment, using the tested worker image's Node executable and a dedicated ACR-pull-only identity with no application/database secrets. It logs only status/ready and never response bodies. Probe failures and missing 15-minute probe heartbeats have separate alerts; missing ten-minute worker sampler heartbeats can mean worker or logging failure. Deployment requires the actual readiness URL, environment/registry names, probe image digest, PostgreSQL name and a capacity-reviewed connection alert threshold. The synthetic probe may wake a scale-to-zero API; measure that cost before pilot acceptance.

`credential_integrity_violation` is emitted only for the two actual credential qualification/public-hash uniqueness constraints. Qualification-processing failure results are distinct domain signals. Credential/publication HTTP 5xx counts are explicitly labeled symptoms and do not prove an issuance or publication integrity defect. Source/AI logs provide provider durations, measured tokens and safe failure outcomes only after durable recording. Estimated and provider-billed money are distinct series; absent or lost log samples must be reconciled with authoritative usage rows before financial conclusions.

Alert thresholds are initial pilot thresholds, not a measured SLA. Alert names map to the following response:

| Alert | First check | Response / escalation |
|---|---|---|
| api-errors / readiness-failed / admission-unavailable | API workbook, readiness, DB connection pool and storage availability | Stop promotion; rollback a compatible image if deployment-induced. Named service operator escalates to database/storage owner. |
| abuse-spike | Counts of denied categories, auth failures and gateway traffic | Investigate abuse; retain global protection. Named security operator checks legitimate shared-proxy traffic before tuning. |
| job-failure / deadletters | Correlation, job state/lease, queue dead-letter reason and provider status | Pause admission, inspect immutable source/release binding, then use existing audited retry API. Never invent a replacement job ID to bypass idempotency. |
| budget-threshold | `operations-admin.mjs status` and Azure cost analysis including storage/egress/monitoring | Pause expensive work and reconcile actual prices; resource-group overhead is not represented by per-job estimates. Named budget owner decides envelope changes. |
| database-pool-wait / database-connection-failures / database-connection-capacity / database-storage-pressure | Native DB workbook and local waiting/active pool counts | Check DB reachability, configured pool totals, native connection quota and storage. Failed connections can also mean bad credentials; do not diagnose exhaustion from that metric alone. Escalate to the named database operator. |
| queue-age / sampler-heartbeat / telemetry-sampler-failure | Broker age observation, sample count/truncation, native ActiveMessages and outbox age | Distinguish intentionally scheduled work from eligible active backlog. Check worker intake and lease fencing. A null observed age is unknown, not healthy/empty. Escalate to the queue operator. |
| api-availability / api-probe-heartbeat | Probe job execution, readiness response, ingestion delay and API revision | Check both the API and the independent probe/log transport. Restore the failing component; never suppress a missing heartbeat by inventing successful probes. |
| provider-failure-or-quota / webhook-email-failure | Failed durable source receipts, rejected AI results, committed retry/failed delivery states and admission codes | Check approved provider availability, quotas, recipient/destination policy and safe retry state. Rejected AI content is an output-validation failure, not necessarily provider downtime. |
| credential-issuance-failure / credential-integrity / publication-failure-symptom | Domain qualification result, exact uniqueness code, HTTP symptom and authoritative credential/release records | Pause affected issuance/publication when integrity fails. Preserve immutable evidence and investigate before replay. An HTTP error alone does not prove duplicate issuance. |

Use the current operator's actual email in deployment parameters and an accessible URL for this runbook. Deliberately trigger each alert in isolated staging and retain redacted delivery evidence before declaring telemetry accepted.

`node tools/check-operational-signals.mjs` checks sampled broker semantics, excluded scheduled/deferred/expired messages, unknown observations, HMAC privacy, throttling, sink-failure isolation and the four workbook/panel signal-field contracts. `node tools/check-queue-telemetry-postgres.mjs` verifies actual cross-organization routing aggregation under the designated non-super/non-bypass publisher role while credential reads remain denied. These local tests do not execute KQL against Azure, validate actual exported metric availability or prove alert receipt.

## Admission and pricing

### Source usage and trusted monetary reconciliation

API/worker storage adapters now emit durable STARTED receipts before I/O and SUCCEEDED/FAILED outcomes with bounded operation counts, payload bytes and elapsed milliseconds. Worker speech records input text character counts, output audio milliseconds/bytes; video records requested/generated milliseconds and output bytes; reconstruction and processing record execution duration/calls plus available input/output byte measurements. Embedding hooks use the same source contract for input characters/tokens. Prompt text, narration, blob keys, access URLs and provider error messages are absent from receipts. Worker tenant context comes from its authoritative job, never an outbound provider response.

Each measured physical invocation has a receipt identity. Receipt replay is idempotent; changing its measurements conflicts. Database-unavailable admission prevents unmetered work starting. If the source operation succeeds but its completion receipt cannot commit, its persisted STARTED receipt is an unknown outcome requiring reconciliation; it is not falsely labeled a failed provider/storage call. Storage `calls` count adapter operations, not every hidden SDK request/retry. `storage.read` bytes measure server downloads; writes measure bytes written during the operation, not retained byte-hours. Signed upload/download grants are counted independently and do not establish actual client transfer. Direct SAS egress and retained storage-time charges still need Azure service billing/inventory measurements. Do not infer those charges from grant counts or cumulative write bytes.

`SOURCE_USAGE_RATES_JSON` optionally supplies at most 64 reviewed rules with `rateId`, `operation`, `provider`, `unit` and integer `microUsdPerMillionUnits`. Empty rules preserve source meters and leave money unknown. A successful receipt can produce separate `ESTIMATED_RATE` cost events; the source receipt, rate version, unit, quantity and rate value are retained. Neither configured reservations nor synthetic test rates establish provider bills. Existing AI deployment/model token estimates remain separate and are not double-counted by generic processing rules.

For actual provider invoices, run `node tools/reconcile-billed-usage.mjs <reviewed-json-file>` using `OPERATIONS_ADMIN_DATABASE_URL` and exact `OPERATIONS_CONFIRM_DATABASE`. The input is a bounded array of `{organizationId,sourceUsageEventId,invoiceLineId,microUsd}`. Use an opaque invoice-line identifier, never personal/banking data. The protected admin identity must have PostgreSQL administrative privileges; a normal runtime connection is rejected. Each line must match an existing tenant source receipt. It creates a distinct audited `PROVIDER_BILLED` cost event, retaining only an invoice hash in audit. Replaying an identical line is safe; altered amounts/source references conflict. A batch can partially commit before a later invalid entry, so repair and replay with the same opaque line IDs. This is an operator tool; there is no customer cost-write endpoint. Estimated and billed totals remain separate and must not be summed as if both represent additional charges.

`node tools/check-source-usage.mjs` exercises the actual restricted PostgreSQL store and local Azurite transfer, receipt replay/conflict, monetary provenance, operator-only invoice reconciliation and tenant boundaries. `node tools/check-provider-usage.mjs` covers trusted provider context, speech/video/reconstruction measurements and safe failed-call receipts. Local rates and provider doubles are explicitly synthetic; real billing/usage samples remain required.

The private `operational_*` tables are not tenant datasets and have no runtime table grants. Runtime receives only the four narrow SECURITY DEFINER functions with a fixed search path and PUBLIC execution revoked. Keys are HMAC hashes, not raw subjects or addresses. Only administrative access can toggle durable `operational_control.paused`.

HTTP has a shared global 6,000 requests/minute ceiling and per-network-address ceiling of 120/minute (30/minute for sensitive lookup/upload/generation/verification paths), plus authenticated-subject limits integrated by the API. Incoming forwarded-address headers are not trusted. Behind an ingress proxy, multiple customers can share the conservative network bucket; measure before configuring a trusted edge policy. A limiter failure returns 503 rather than bypassing protection. JSON bodies are capped at 64KiB by the edge and narrower application limits still apply. Only the exact binary upload PUT route allows 128MiB; the upload session checks authoritative declared size/checksum independently. Requests/headers are bounded to 30/10 seconds. A timeout response does not undo an already committed mutation: clients must reuse idempotency keys and reconcile status. Database and provider timeouts bound their own execution.

Every paid execution needs an explicit worst-case cents reservation validated against actual token/compute/storage/egress pricing. The AI output token limit remains 4,000. A provider that can incur unbounded cost is not safe to enable. Upstream input/context tokens and engine duration must fit the reviewed reservation; a token-output bound alone is insufficient. Reservations never refund to below their estimate, even on failure. Unknown crashed calls stay charged conservatively. Retries use separate persisted job attempt/generation keys, and terminal/duplicate jobs must be checked before reserving. Admission pause, budget denial and capacity denial must not start providers. Queued denials use bounded delayed retry, not an immediate abandon loop.

`withOperationalAdmission` renews ownership every lease/3, aborts on renewal failure and requires a valid token at settlement. Callers must honor its abort signal before effects, kill bounded subprocesses and use the existing processing-job lease-generation fence for final writes. A generic AbortSignal cannot forcibly cancel a remote provider that has already accepted work. Expired duplicate reservation keys are never executed again; operator reconciliation determines whether retrying under a new recorded attempt is safe.

## Pause, drain and rollback

`node tools/operations-admin.mjs status` reports only aggregate reservations. Set `OPERATIONS_ADMIN_DATABASE_URL` from a protected operator environment. Set `OPERATIONS_CONFIRM_DATABASE` to the exact database name for `pause` or `resume`. Pause admission first, then inspect active executions until they complete or reach fenced timeout. Do not revoke a worker's keys or kill it while assuming its paid calls rolled back.

`tools/operations-control.ps1` prints a plan by default. Mutations require `-Execute -ConfirmResourceGroup <exact group>`. `PauseQueue` sets Service Bus ReceiveDisabled; it stops delivery but allows publishing. Resume only after jobs/storage/provider bindings and usage are reconciled. Application shutdown stops new requests and drains open requests before pool disposal. Worker close must stop intake then wait for active handlers. For rollback, use `-Action Rollback -ContainerApp <name> -ImageDigest <tested compatible digest>`; it changes the app image and never reverses the database schema. Run readiness, the headless certification path and existing idempotent retry checks after rollback. Replay DLQ entries only after root cause repair, using the existing operator API/audit path.

## Recovery rehearsal

The data template configures 35-day PostgreSQL backup retention, Blob versioning/30-day soft delete and Key Vault purge protection/90-day recovery. Backup creation is managed by Azure; these settings alone do not demonstrate a 15-minute RPO. Regional database backup is an explicit creation-time parameter and defaults Disabled for existing deployments. A region string in another configuration is not regional recovery. Confirm supported-region replication, restore capability and storage redundancy in actual inventory.

1. Agree a numeric RTO with the pilot owner before the drill. Record UTC incident time and the last successful write time; target RPO is <=15 minutes.
2. Pause admission and consumers. Capture protected database/Blob inventory and a hash snapshot with `operations-admin.mjs snapshot <new path>`. The snapshot contains counts/hashes only and refuses to overwrite an existing artifact.
3. Plan `operations-control.ps1 -Action RestorePostgres -ResourceGroup <group> -PostgresSource <server> -PostgresTarget <distinct-name-recovery> -RestoreTimeUtc <UTC instant>`. Execute only into the isolated target. Recreate network/private DNS/access configuration; never expose recovery data publicly.
4. Restore private Blob versions and required keys/config to isolated resources. The database does not restore Blob bytes. Verify release manifest hashes, credential records and referenced object checksums; `operations-admin.mjs compare <snapshot>` checks exact DB record hashes when comparing the same frozen recovery point. Legitimate post-snapshot writes require explicit incident-window reconciliation rather than ignoring a mismatch.
5. Reapply the durable withdrawal/deletion/consent tombstones using lifecycle reconciliation before delivery/discovery resumes. Verify revoked and withdrawn artifacts remain suppressed even if an older backup contains their bytes.
6. Run restricted-role tenant, credential/public verification, source suppression, outbox replay and provider-private-delivery checks. Measure achieved data-loss interval and elapsed recovery time. Store redacted evidence and defects. Remain paused if RPO, agreed RTO or tombstone reconciliation fails.

## Secret rotation rehearsal

`operations-control.ps1 -Action StageSecret` writes a new Key Vault version from a protected local UTF-8 file and prints only the version ID. It does not declare the rotation complete. Do not change the signing secret in place while old queued messages remain signed by the old key. Pause admission, drain queued/inflight messages, verify no DLQ/retry items require the old verifier, deploy new matching publisher/consumer configuration and resume after a signed delivery succeeds. Retain the previous version for compatible rollback until the queue/lease/retry horizon expires. Existing single-key verification requires drain for signing-key rotation; overlapping verification is not claimed.

Use provider secondary keys to stage replacement credentials while the current key remains valid, restart/refresh both API and worker revisions, execute a real provider call and only then revoke the old key. Rotate PostgreSQL roles using a separately provisioned replacement login with the same restricted grants, test readiness, switch runtime/outbox consumers, drain old sessions and revoke the old login last. For email-verification HMAC secret changes, pending codes must be invalidated and new challenges issued; never silently accept old evidence with an unrelated key. Repeat for webhook/notification keys following their scoped integration contracts. Record actual staging results; no rotation rehearsal has been performed by these local tests.

## Verification commands

### Separate privileged migration job

`infra/azure/database-migration-job.bicep` deploys a manual, single-replica migration job using a dedicated identity with only its three database-password secret readers and ACR Pull. The worker image includes `tools/migrate-database.mjs` and the compiled bootstrap module. The runtime worker has no administrator secret reference and does not run migrations. Run the manual job before promoting API/worker images. The CLI requires explicit matching database confirmation and admin/runtime host/database bindings; it emits stable error codes rather than URLs, passwords or PostgreSQL exception details. A single-session advisory lock serializes migration invocations, including retry executions. Additive schema changes and grants rerun idempotently; a failed migration must be repaired/retested before retry or promotion.

### Private malware scanner deployment

Build `Dockerfile.scanner` with a supported reviewed official ClamAV release pinned by digest in `CLAMAV_IMAGE`; the build rejects floating tags. Deploy the resulting immutable image using `infra/azure/clamav-service.bicep` in the worker's private Container Apps environment and pass its `clamavHost` output to the worker template. The scanner has internal TCP ingress only, one bounded replica with 2 CPU/4GiB, four scanner threads/eight queued scans, 128MiB stream/file bounds, 256MiB expanded scan bound, archive recursion/file limits and alerts on exceeded/encrypted inputs. FreshClam updates run 24 times daily; startup rejects signature databases older than two days. Permit only the required ClamAV database DNS/HTTPS egress. Alert on updater failure and signature age; startup freshness checks alone do not prove continuous update health. Ephemeral replicas use preloaded official database images; each restart may download signature updates and those costs must be included in pricing review. Confirm actual EICAR rejection, clean-file passage, stale/missing signatures, engine crash and scanner timeout in isolated staging before accepting the scanner service.

Configuration follows [official ClamAV Docker guidance](https://docs.clamav.net/manual/Installing/Docker.html) and the [official daemon configuration sample](https://github.com/Cisco-Talos/clamav/blob/main/etc/clamd.conf.sample). No ClamAV image has been pulled, built or security-approved by these local source checks.

API/worker templates now receive matching webhook and invitation key rings through dedicated Key Vault references. Worker invitation and lifecycle emails use the same configured ACS sender and managed identity email-send role, with bounded global/organization rates. Set an active invitation key shared with the API. Cost template parameters remain conservative planning placeholders (AI/asset 100 cents, reconstruction/video 1,000 cents, lesson 500 cents); deployment requires explicit `costReservationsReviewed=true`, and operators must replace values that do not cover actual worst-case workloads. Enabling `multi-view,video` and FFmpeg/FFprobe wiring does not clear engine licensing or constitute real-capture acceptance.

It requires the disposable test database on port 54329 and cleans only its own prefixed keys. These tests do not measure production throughput or prove delivery to Azure alert recipients.
