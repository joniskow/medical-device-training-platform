# Image and video inspection

The Azure worker routes image/video uploads through real FFprobe/FFmpeg inspection rather than the pilot placeholder. Supported profiles are PNG, JPEG, WebP, H.264 MP4 (420 pixel format, optional AAC audio), and VP8/VP9 WebM (optional Opus/Vorbis audio). Other profiles fail validation. Inputs are bounded to 128 MiB, 4096 pixels per axis and five minutes for video.

After checking the tenant prefix and source SHA-256, the worker probes local media, restricts demuxers/protocols, decodes the admitted file and creates a preview PNG plus a JSON report in private storage. Reports retain source identity, dimensions, duration, codecs and successful decoding. Retries use deterministic artifact paths. Processing remains REVIEW_REQUIRED and does not claim reconstruction, transcription, rights clearance or clinical suitability.

Subprocess limits are 15 seconds for probing/preview and 60 seconds for full decoding, with bounded captured output. Temporary files are removed after each attempt. Storage errors remain retryable; decoder failures reject the source.

`tools/check-media-processing.mjs` tests actual media generation/decoding, persisted previews/reports, repeat-stable artifact paths, hash/tenant checks and corrupt-input rejection. Author media review and private learner delivery are implemented locally and have separate acceptance checks; deployed browser acceptance remains open.

## Timestamped video review, 2026-10-31

Adapter version 2 samples at most 24 frames over the source duration using FFmpeg's `select` and `showinfo` filters. It records original decoded presentation timestamps, a SHA-256 and byte length per PNG, deterministic tenant/source-hash artifact paths, unique-frame count and an identical-frame warning. Images remain bounded to 640 pixels per axis, 2 MiB each and 24 MiB total. Frame extraction has a 45-second timeout and bounded subprocess output in addition to existing input/decode limits. All frame generation finishes before persistence; the inspection report is written last. Storage failures remain retryable and retries reuse artifact paths.

The author review gallery fetches authenticated, no-store frame bytes through `/api/v1/media-review/{assetVersionId}/frames?index=N`. API validation checks source lifecycle/tenant, report bounds, derived artifact path, frame index, content length and hash. Blob keys are not returned to the browser. Old reports without frames remain usable; reprocessing is needed to add a gallery.

Reviewers can load the full private video, inspect the sampled views, and select a timestamp to seek the video. Frame load/decode failures permit retry. Closing or changing account/organization aborts pending loads and revokes object URLs. The full source preview and explicit rationale/confirmation are still required to expose and record a decision. Review thumbnails alone do not prove coverage, scale, rights, suitability or reconstruction quality.

Verification: `pnpm media-review:validate` requires the local development PostgreSQL database. `pnpm media-review:browser` requires `output/media-review/source.mp4`, `inspection.json` and `frame-N.png` generated by the real-worker check with `MEDIA_EVIDENCE_DIR` set. The latter test uses isolated Chrome and local synthetic media, with no live user account or external service. Worker acceptance ran with networking disabled, 768 MiB and two CPUs using the existing `medical-device-worker:media` image and mounted current compiled processor. Both MP4/WebM static fixtures and a moving H.264 fixture pass; the moving clip yields 24 ordered views while static clips produce duplicate warnings. This does not claim a newly built/deployed worker image.

Browser evidence: `output/media-review/gallery.png`. Database/HTTP tests include frame authorization, malformed/duplicate queries, absent frames, tampered hashes/lengths/paths/timestamps and legacy reports. Browser checks include real PNG/video decoding, seeking, retry, inert filenames, responsive layout, explicit review and late-response/sign-out cleanup. Source-document review shares the corrected checkbox layout.

Actual image/video-to-3D reconstruction remains unfinished. These thumbnails support visual review; an engine needs appropriate full-resolution overlapping captures, scale evidence, camera registration, geometry/texture generation and candidate quality review.
