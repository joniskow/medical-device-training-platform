# Activity structure authoring

The course editor supports moving activities up and down within a module and confirmed removal of an unreferenced activity. Moves retain activity IDs, assessment IDs and source references, and use the existing draft autosave/revision workflow. After rerender, keyboard focus stays on the moved activity or returns to its module after deletion. The first/last move buttons are disabled at their boundaries.

Removal is blocked when an activity is referenced by a story node, prerequisite or choice condition, explicitly required by certification policy, or inside a required/requalification update module. Authors must first revise those references deliberately. Simulation activities are also guarded because deleting their activity alone would leave the course simulation binding inconsistent; binding replacement/removal is still a separate authoring gap. Empty draft modules remain editable and publication validation rejects them. Published releases are never changed by these controls.

Local evidence (2026-10-30): web build and architecture checks pass. The integrated Chrome editor regression verifies move boundaries, persisted order, stable identities, focus after movement/deletion, cancellation, successful unreferenced removal, and separate story-only/required-activity guards. Existing story, assessment, simulation, autosave, conflict and sign-out checks continue to pass. This is controlled browser coverage, not deployed acceptance or completion of the entire activity catalog.

## Guided procedure, manipulation and assembly

Bound simulation activities now expose an Interactive activity type selector for Simulation, Guided procedure, Component manipulation, Assembly/disassembly, Fault troubleshooting and Simulation outcome assessment. The selector retains the activity and simulation definition IDs. Authors configure the actual steps, component transforms/actions, scoring and equivalent instructions in the existing simulation editor; changing the label does not invent new procedural behavior.

Guided procedure, manipulation and assembly now receive published simulation runtime bindings and learner launch controls. Publication requires their simulation definition binding. Certification, story facts/preview, selected-module requalification and public catalog disclosures classify these activities as scored simulations rather than passive content. They use the existing server-authoritative interpreter, approved-model action constraints, attempt history and credential evaluation. This does not add rigid-body physics, independently bound simulations per activity, standalone viewer/hotspot authoring, or prove physical assembly fidelity.

Evidence (2026-10-30): full build, schema and architecture checks pass. Pure publication tests reject missing bindings for each type. Author Chrome saves each selection with stable binding; learner Chrome issues the correct launch requests and preserves server denial feedback. Local PostgreSQL covers guided procedures in a published story, manipulation with persisted transforms and attempt/credential lifecycle, and assembly with a branched procedure and the same lifecycle. Each case verifies public certification disclosure as simulation evidence with its score threshold. These use synthetic reference geometry and controlled services, not deployed or physical-device acceptance. Run pnpm interactive-catalog:validate.
