# PDF to editable AI course

The deployed worker previously used a smoke-only asset processor. A real PDF processor is now wired into the Azure worker runtime for PDF assets; other types retain their existing adapter. It reads the private blob, verifies its checksum, extracts machine-readable text with pinned pypdf, creates stable page/character citations without dropping boundary words, writes a private extraction artifact and indexes passages for source selection. The durable worker then moves the version to READY_FOR_REVIEW. Empty-text PDFs fail with PDF_OCR_REQUIRED; mixed text/empty PDFs disclose pages needing OCR. Encrypted and oversized documents fail explicitly. This implementation is text-PDF extraction, not OCR or production malware screening.

The worker image now includes Python/pypdf and the extraction script. Missing schema-package dependencies and build order in Dockerfile.worker were corrected. The Docker image medical-device-worker:pdf builds and imports the packaged processor successfully. Container rollout is still pending.
